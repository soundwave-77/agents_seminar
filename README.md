# Семинар: агент для планирования путешествий

Помощник на OpenAI Agents SDK с инструментами MCP, генерацией и оценкой диалогов через DeepEval и трейсингом в Langfuse.

- [HOMEWORK.md](HOMEWORK.md) — задание, критерии оценки и формат сдачи.
- [SOLUTION.md](SOLUTION.md) — метрики базового ReAct и результаты выбранных паттернов.

```text
.
├── app.py                          # Точка входа и навигация Streamlit
├── travel_agent/                   # Агенты, инструменты и запуск

│   │   ├── react.py                # Готовый ReAct
│   │   ├── reflection.py           # Заготовка Reflection

│   │   └── instructions/
│   │       └── react.md            # Инструкции ReAct
│   ├── runner.py                   # Общий запуск агента: run_agent()
│   ├── mcp_servers.py              # Подключения к MCP-серверам
│   ├── tools.py                    # Инструмент получения текущей даты
│   └── tracing.py                  # Настройка трейсинга в Langfuse
├── ui/                             # Интерфейс и состояние приложения
│   ├── agent_session.py            # Выбор агента, подключения MCP, история
│   └── pages/
│       ├── chat.py                 # Чат с выбранным агентом
│       ├── dialogue_generation.py  # Генерация диалогов и сохранение в Langfuse

│       ├── task_completion.yaml    # Выполнение задачи
```

Функции создания агентов в `travel_agent/patterns/` уже подключены к выбору паттерна в интерфейсе.

MCP-подключения:

- PilotPlans — жильё.
- Fli — билеты.
- Keenable — места и досуг.
- Weather — погода.

Диалоги и трейсы сохраняются в Langfuse.

Судьи оценивают переписку, но не подтверждают актуальность цен и доступность предложений.

**Результаты оценки хранятся только в сессии Streamlit** и автоматически в Langfuse не записываются. Перенесите метрики в `SOLUTION.md` до закрытия сессии или оценки следующего датасета.

## Настройка и запуск

Python 3.13+, `uv`. Команды выполняются из корня репозитория.

### Создание проекта в Langfuse

1. Зарегистрируйтесь в [Langfuse Cloud](https://cloud.langfuse.com) или войдите в Langfuse по адресу, который предоставил преподаватель.
2. Выберите организацию. Если её ещё нет, создайте через «New Organization».
3. В меню выбора проекта нажмите «New Project» и создайте отдельный проект для своей работы.
4. В проекте откройте **Settings → API Keys** и создайте пару ключей. Скопируйте Public Key в `LANGFUSE_PUBLIC_KEY`, Secret Key — в `LANGFUSE_SECRET_KEY` файла `.env`. Секретный ключ показывается только при создании.
5. В `LANGFUSE_BASE_URL` укажите адрес вашего сервера Langfuse без пути к проекту. Для Cloud используйте адрес выбранного региона, например `https://cloud.langfuse.com`.

Диалоги и трейсы будут сохраняться в проект, которому принадлежат эти ключи. Подробнее — в [документации Langfuse](https://langfuse.com/docs/administration/rbac#api-keys).

### Подключение и запуск

Скопируйте шаблон в `.env`:

```bash
cp .env.example .env
```

Заполните в `.env`:

- `OPENAI_BASE_URL` и `OPENAI_API_KEY` — из Stepik.
- `LANGFUSE_SECRET_KEY`, `LANGFUSE_PUBLIC_KEY` и `LANGFUSE_BASE_URL` — из своего проекта в Langfuse (см. выше).

**Не меняйте модели, уровни thinking и параметры вызовов: ключ общий, бюджет ограничен.**

```bash
uv sync
make run
```

Подключения MCP приложение открывает автоматически. После ошибки соединения из-за простоя перезапустите приложение. Если генерация постоянно повторяет одну ошибку, остановите её и проверьте логи: число повторных попыток не ограничено.

## Проверки

| Команда | Действие |
| --- | --- |
| `make test` | Тесты из `tests/` |
| `make lint` | Проверка Ruff |
| `make format` | Форматирование Ruff |

Проверки функций создания агентов сообщают о заглушках и ошибках предупреждениями, которые не останавливают тесты. Работу реализованных паттернов проверьте в чате.
